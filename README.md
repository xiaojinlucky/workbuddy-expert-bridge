# WorkBuddy Expert Bridge

**让 Codex、Cursor、Claude Code、Grok、VS Code 等本地 AI 工具，继续使用你电脑里已经安装的 WorkBuddy 专家与专家团。**

换了 AI 工具，不必让它从通用提示词重新开始，也不用给每个工具重新配置一套专家。说清楚你要完成什么，它会先推荐合适且本机可用的候选；你确认后，再复用已有的成熟工作流。

| 会帮你选 | 会帮你核验 | 会先替你把关 |
| --- | --- | --- |
| 自然语言推荐最多 3 个真正相关的候选 | 说明分类、专家类型、本地可用性与排名依据 | 默认避开需要扫码、充值、外部导流或来源不明的候选 |

## 一分钟开始

把下面这句话发给支持 Agent Skills 的本地 AI 开发工具：

```text
请帮我安装这个 Skill：https://github.com/xiaojinlucky/workbuddy-expert-bridge
```

也可以使用命令安装：

```bash
npx skills add xiaojinlucky/workbuddy-expert-bridge --skill workbuddy-expert-bridge
```

如果当前工具没有自动识别，请在它自己的 **Skills 安装入口**中导入这个 GitHub 仓库；不同工具的入口名称可能略有不同。

安装以后，直接发送第一个请求：

```text
请根据我的需求推荐最合适的 WorkBuddy 专家或专家团。先给出最多 3 个候选、推荐理由、本地可用性和排名证据；我确认后，再使用第一名协助完成任务。
```

Skill 自身不需要账号、密钥或额外配置。WorkBuddy 与当前 AI 工具需要位于同一台电脑，并且当前工具需要拥有读取本机文件的权限。

## 三步复用已有专家

```text
本机已有 WorkBuddy 专家
          ↓
在当前 AI 工具中说清任务目标
          ↓
获得候选与依据 → 确认后复用第一名
```

例如，你可以直接说：

```text
我要策划一个面向科研新手的小红书系列。请推荐最合适的 WorkBuddy 专家或专家团，
说明为什么适合、是否已在本机可用，以及哪些排名信息能够核验。不要为了凑数给弱匹配。
```

你会先看到候选和选择依据，而不是让某个名字听起来合适的专家直接接管任务。

## 它适合解决什么

| 你的情况 | 这个 Skill 提供的帮助 |
| --- | --- |
| 知道要完成什么，但不知道该选哪位专家 | 根据自然语言需求推荐最多 3 个合格候选 |
| 已经在 WorkBuddy 中安装了成熟专家，希望换一个 AI 工具继续使用 | 让当前工具复用专家或专家团的现有工作流 |
| 推荐看起来合适，但不确定本机能否立即使用 | 分开说明匹配程度与本地可用性 |
| 担心专家包夹带扫码、充值、推广或外部注册要求 | 默认不让这类候选悄悄进入正常推荐 |
| WorkBuddy 的最热、最新或综合排名无法核验 | 明确显示 `unavailable`，不使用猜测补齐 |
| 没有足够合适的候选 | 返回更少结果或明确说明没有匹配对象，不凑满 Top 3 |

## 一次推荐包含什么

每个候选都会说明：

- 为什么适合当前需求；
- 属于哪个场景分类；
- 是单个专家还是专家团；
- 是否已在本机安装并通过可用性检查；
- 相关性、分类、最热、最新和综合排名中，哪些证据能够核验。

推荐只负责缩小选择范围，不会替你安装、下载或启用专家。确认候选以后，可以继续要求当前 AI 工具使用第一名处理任务。

## 用起来有边界，也有交代

- **不改变原来的 WorkBuddy**：只读使用现有信息，不修改你的专家与配置。
- **不把风险藏起来**：需要扫码、充值、外部注册、推广导流或存在异常的候选，会被避开或明确标记。
- **不确定就直说**：排名取不到就显示 `unavailable`，包损坏就提示修复，不用猜测伪装成功。
- **不替你擅自行动**：不会替你安装陌生内容；涉及账号、付款、上传或其他外部动作，仍需要你明确决定。

这些检查用于减少误选风险，不是对第三方专家包的安全认证。当前 AI 工具如何处理任务上下文，仍以该工具的数据政策和你的配置为准。

## 兼容性

| 环境 | 当前状态 |
| --- | --- |
| Grok Build + Windows | 已完成项目级 Skill 的真实端到端验证 |
| Codex、Cursor、Claude Code、VS Code 等本地 AI 开发工具 | 具备 Agent Skills 能力且可以读取本机 WorkBuddy 文件时可用 |
| macOS / Linux | 已完成静态兼容审查，尚未真实运行验证 |
| 普通网页或移动端 AI 对话服务 | 默认无法直接读取本机 WorkBuddy |

公开版本已经通过自动化回归，并完成一个非 Codex 宿主的真实端到端运行。没有经过真实验证的平台能力，不会标记为已经验证。

## 与 WorkBuddy 的关系

WorkBuddy 继续负责提供和管理专家；这个 Skill 负责把已有的成熟工作流带到你正在使用的本地 AI 工具中，不改变你在 WorkBuddy 里的专家与配置。

如果你也在多个 AI 工具之间来回切换，欢迎点一个 **Star**。它既方便你以后找回来，也能让更多 WorkBuddy 用户少走一遍“从零搭专家提示词”的弯路。

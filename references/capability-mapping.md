# 宿主能力映射与专家团编排规范

## 能力状态

每项能力必须客观标注为：

- `AVAILABLE`：当前宿主提供并已确认可用接口；
- `PARTIAL`：只能完成部分语义（如仅能读不能写）；
- `UNAVAILABLE`：当前宿主没有该能力；
- `BLOCKED`：能力存在，但权限、环境或状态阻止使用；
- `NOT_APPLICABLE`：当前任务不需要。

不要从宿主品牌名称臆测能力，也不要为匹配 WorkBuddy 工具名而凭空发明接口。

## 具象专有工具映射与拦截红线

专家 Markdown 正文中常常包含 WorkBuddy / CodeBuddy 原生的工具调用指引。必须按以下规则进行转换：

| WorkBuddy 专有接口/意图 | 通用宿主对应能力 | 缺失时的处理与降级 |
| --- | --- | --- |
| `sendMessageToAgent(agentId, msg)` | 隔离子 Agent（如 `invoke_subagent`） | 降级为单 Agent 顺序交接（Role Handoff），严禁假冒多进程并发 |
| `create_task` / `update_task` | 宿主计划工具或 Markdown 结构化清单 | 使用宿主现有任务计划能力；无能力时记录在会话上下文清单 |
| `codebuddy_browser` / `codebuddy_search` | 宿主网页抓取与搜索工具 | 标为 `UNAVAILABLE`，明确说明缺少网络检索事实依据 |
| `codebuddy_terminal` / `run_script` | 宿主命令行执行工具（如 Bash / PowerShell） | 输出可复现脚本命令并标为未执行，严禁伪造执行通过证据 |
| `read_file` / `write_file` / `edit_file` | 宿主文件读写与局部编辑工具 | 缺失写权限时停止破坏性修改，仅输出拟修改差异建议 |
| 自定义 MCP / 专有插件能力 | 宿主已配置并验证的 MCP / 扩展工具 | 标为 `UNAVAILABLE`；若为关键依赖则阻塞受影响流程 |

> [!CAUTION]
> **工具调用拦截红线**：严禁直接以专家正文中的 WorkBuddy 专有字面名（如 `sendMessageToAgent`、`codebuddy_browser`）发起宿主 Tool Call。遇到未映射的工具必须显式声明降级或阻塞，禁止因调用未知工具引发宿主系统异常。

## 专家团执行与标准交接协议 (Role Handoff Protocol)

### 1. 编排模式选择

1. **隔离委派模式 (`delegated-team`)**：
   - 适用前提：宿主具备独立子 Agent 隔离执行环境、各角色产物可独立验收。
   - 执行原则：给每个隔离子 Agent 最小化输入、明确交付物与停止条件；团队主理人（`leadAgent`）负责整体统筹、冲突仲裁与终审整合。
2. **顺序降级模式 (`sequential-team`)**：
   - 适用前提：宿主缺乏子 Agent 隔离能力，必须在当前单一 Agent 会话中串行完成多角色任务。
   - 执行原则：必须严格遵循下述**上下文隔离铁律**与**标准交接协议**，严禁将不同角色的意见混杂为一段泛化回答。

### 2. 上下文隔离铁律 (Context Isolation Rule)

- **逐次加载**：单 Agent 顺序执行时，**严禁将专家团全部成员的 Prompt 指令一次性全量注入上下文**（易引发弱模型“人格混同”或单轮虚假自问自答）。
- **按阶段注水**：进入某一角色的执行回合时，仅加载该角色的指令正文与前一角色的交接交付物；任务完成后封存该角色产物，再交由下一角色处理。
- **主理人终审**：所有成员角色执行完毕后，主理人必须具备独立的最终回合，对照需求进行质量门禁验收。

### 3. 标准交接块格式 (Standard Handoff Block)

在 `sequential-team` 降级执行中，角色间交接必须使用统一的结构化交付块：

```markdown
### [Role Handoff: <发送方角色> -> <接收方角色/主理人>]
- **执行阶段 (Phase)**: <阶段编号与名称，例如 Phase 1: 需求拆解与架构设计>
- **角色职责**: <本角色在该阶段的核心职责定义>
- **输入依赖**: <上一角色的交付产物引用或原始用户需求>
- **核心产出与结论**: <本轮交付物路径、关键决策或方案设计>
- **质量门禁状态**: <PASS / NEEDS_REVISION>
- **移交待办**: <移交给下一角色的具体执行要求与约束条件>
```

# 推荐与排序证据

本页是 `recommend` 的稳定运行策略。具体版本、一次性机器取证和日期化结果不参与日常推荐；只有审计排序语义或维护匿名探针时才读取 [排序取证记录](ranking-audit-2026-08-28.md)。

## 证据层级

| 证据 | 可回答的问题 | 不得声称 |
|---|---|---|
| 本地可读专家包 | 是否存在可读角色、能否在当前机器执行 | WorkBuddy 官方热度或综合排名 |
| 本地目录快照 | 分类、展示元数据、快照时间 | 实时最新榜 |
| 官方公共目录 | 公共目录中显式提供的字段 | 未显式提供的排名值 |
| 官方匿名实时响应 | 候选全集中完整、显式的实时字段 | 登录后数据或未覆盖候选的值 |

只有清单存在但没有可读角色 Markdown 的包是 `installed-unusable`，不能算作本地可用，也不能进入推荐结果。没有进入目录快照的本地可读包仍属于推荐候选池，但其分类、热度、最新和综合证据按真实缺失状态报告。

## WorkBuddy 排序语义

| UI 排序 | 字段 | 使用条件 |
|---|---|---|
| 综合 | `reco_rank` | 候选全集都有显式值时才可用 |
| 最热 | `use_count` / `useCount` | 候选全集都有显式值时才可用 |
| 最新 | `published_at` | 官方实时值完整时可称实时最新；本地 `createdAt` 只能称快照时间 |

`displayPosition` 是运营位置，不是人气数。文件顺序、界面卡片顺序、创建时间和推荐器自己的相关性分数都不能替代热度或综合排名。

## 推荐决策

1. 合并本地目录条目与未进入目录的可读本地包，按稳定身份去重。
2. 先检查自然语言需求与名称、专业定位、标签、描述和分类的可解释匹配。
3. 只有高信息需求词直接命中候选，或用户显式限定分类并存在语义匹配时，候选才合格。弱泛化词不用于补齐 Top 3。
4. 明确的 `agent|team` 意图和本地 `installed` 状态只作有限调整，不能让不相关候选越级。
5. 只有完整可核验的 `useCount` 才能作为次级排序证据；缺失时 `hot.status=unavailable`。
6. 本地时间字段只作快照同分证据；`reco_rank` 缺失时 `comprehensive.status=unavailable`。
7. 用户明确要求官方实时核验时才启用匿名探针。认证失败、字段部分覆盖、格式错误或重定向都保持 `unavailable`，不得恢复凭据或从 UI 推断。

每个返回候选必须携带逐字段相关性、本地可用性、分类、最热、最新和综合证据。返回少于 3 个或 `no-match` 是正常结果，不是需要用弱匹配掩盖的失败。
